A scenario range is not a probability claim

Build an effort envelope, test a capacity limit and explain what a range cannot promise.

Fictional practice packet. Use “In this example…” when explaining an answer. Every company, person and measurement below is invented. The exercise is self-contained; a calculator is optional and no code is required.

Data and definitions

Fictional Fir Reports prepares manually checked document bundles. A bundle is one unit of work. Total effort is setup minutes plus bundle count multiplied by active processing minutes per bundle. Work is sequential for one person; there is no parallel processing. The person has 180 minutes available. Breaks, interruptions and rework are excluded from this simplified packet, so the exercise does not establish a real delivery commitment.

Calculate before reading the key

Determine the maximum whole number of bundles that fits in 180 minutes when setup and per-bundle time both take their high values.

For a second planning question, keep twelve bundles and fifty setup minutes fixed. Calculate the largest average processing time per bundle that fits capacity. Draft an explanation that preserves the useful range while rejecting the unsupported probability label.

Worked answer key

At the low combination, total effort is 30 + 8 × 10 = 110 minutes. The reference combination is 40 + 10 × 13 = 170 minutes. The high combination is 50 + 12 × 16 = 242 minutes. Against 180 available minutes, the low combination leaves 70 minutes, the reference leaves 10, and the high exceeds capacity by 62. A reference scenario that fits does not imply that all permitted scenarios fit.

The formula increases when any input increases, and the packet allows the extreme combinations. That makes 110 to 242 minutes a mathematical envelope under the stated model. It is not a claim that all actual work will stay in that interval: interruptions or values outside the assumed bounds would break the model. Nor does the interval assign likelihoods to any point inside it.

At the high setup and processing values, solve 50 + 16 × bundles ≤ 180. The remaining processing budget is 130 minutes. Dividing by 16 gives 8.125 bundles, so the largest whole count is eight. Eight uses 50 + 128 = 178 minutes, leaving two. Nine would require 194 minutes, exceeding capacity by 14. Rounding 8.125 upward would violate the capacity constraint.

For twelve bundles with fifty setup minutes, the processing-time limit is (180 − 50) / 12 = 10.83 minutes per bundle rounded to two decimals. The exact threshold is 65/6 minutes. The rounded number is a communication aid; use the exact value when checking the boundary. This is the required average under the model, not evidence that a worker can sustain it.

Practice follow-up

Ask a partner, “What is the chance we finish in three hours?” A supported response says the reference scenario fits, the high scenario does not, and no probability can be calculated from these inputs alone. Do not manufacture equal likelihoods for low, reference and high, or average them and call that an expected duration.

Then ask which input would be useful to learn first. The answer can depend on what is uncertain and cheap to observe. Confirming the actual bundle count removes one source of uncertainty. Timing representative bundles may inform processing assumptions. Neither action automatically establishes a probability distribution or eliminates interruptions.

Limits of the conclusion

Three hours equals 180 minutes, but active processing effort and elapsed completion time match here only because the packet assumes sequential uninterrupted work. Real scheduling can have waits, dependencies and changing scope. The high inputs are not evidence of a particular confidence level. If extreme inputs cannot occur together in reality, the envelope may be conservative; that would need an explicit dependency rule. If hidden tasks are missing, it may be too optimistic. Explain those limitations instead of presenting scenario arithmetic as a forecast guarantee, and never describe the fictional workload as your own delivered project.
